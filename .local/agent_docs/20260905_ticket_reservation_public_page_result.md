# 公開チケット予約ページ 実装結果

## 実装結果

- `/tickets/:slug` の公開予約ページを追加した。
- 公開イベント、予約枠、残数を取得し、満席などDB取得値に応じて選択可否を制御した。
- request IDを保持して予約RPCの冪等再送を可能にした。
- 予約RPC成功後にレスポンス取得だけ失敗した場合、受付終了や枠開始後でも保持済みrequest IDによる再送だけを許可した。
- `reservationRequestId` を保持している間は予約枠radioだけでなく名前・メール・枚数・備考も固定し、再送payloadを変更できないようにした。
- DB/PostgRESTから構造化されたエラーコード付きの確定エラーが返った場合はrequest IDを解除し、公開イベント・在庫を再取得してから次の操作へ進めるようにした。結果不明の通信失敗ではrequest IDを保持する。
- 確定エラー後の再取得にも失敗した場合は古い在庫を使い続けず、予約ページをエラー状態へ落として再読み込みを促す。
- 満席スナップショットが後からキャンセル等で変化した場合に回復できるよう、「空席状況を更新」ボタンで公開イベント・予約枠・残数を手動再取得できるようにした。自動ポーリングは追加しない。
- 予約成功後の再取得がエラーまたは `data: null` の場合も、現在のイベントと予約番号表示を維持するようにした。
- 受付期間・枠開始時刻に関する端末時計判定は案内と優先選択に限定し、公開状態と残数を満たす場合はRPCへ到達可能にした。最終的な時刻判定はDBの `clock_timestamp()` と行ロックを権威とする。
- 端末時計上で開始済みの枠は開始前の枠より後に選択候補とするが、時計ずれだけを理由に確定的には無効化しない。
- `closed` かつ予約枠履歴のないイベントは「自由席として受付中」と案内せず、「予約受付は終了しました」と表示する。
- 次の予約入力または新しいrequest IDでの送信開始時に前回の予約番号表示をクリアし、失敗した新規予約と過去の成功表示が同時に出ないようにした。
- 入力や予約枠を変更した時点で以前のエラー表示もクリアし、解消済みエラーを残さないようにした。
- 予約枠履歴だけが残り現在の枠が0件の場合は案内を重複表示しない。
- 公開イベント取得は共通helper側で埋め込みalias `windows` を使って予約枠を並べ替え、可用性RPCに存在しない削除済み可能性のある枠を除外する。

## レビュー対応

- 受付境界後の冪等再送と、成功後再取得 `data: null` 時の予約完了表示維持に対応した。
- 通常時の入力変更と、冪等再送待ち中のpayload固定を状態で分離した。
- DBが明確に拒否した確定エラーではrequest IDを解除して公開状態・残数を再取得し、再取得不能なら古いスナップショットを無効化する。通信結果が不明な場合だけ冪等再送待ちを維持する。
- 端末時計ずれへの対応としてサーバー時計同期機構は追加せず、クライアント時刻を確定的な受付拒否に使わないよう単純化した。受付開始・終了・枠開始の最終判定は既存DB RPCへ一本化した。
- 在庫変化への追随は自動ポーリングではなく明示的な手動更新導線とし、常時同期stateを増やさない方針とした。
- `closed` 自由席イベントの案内を受付終了へ修正した。
- 入力変更時の旧エラー表示と、予約枠0件時の重複案内を修正した。
- 親StackのDB・共通クライアント・管理画面のレビュー修正と簡素化を同期した。

## 検証

- GitHub Actions CIで継続検証する。
- 公開予約ページ固有の挙動と親Stackの差分を分離した状態で維持する。
