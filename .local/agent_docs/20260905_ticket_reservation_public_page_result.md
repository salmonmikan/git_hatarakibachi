# 公開チケット予約ページ 実装結果

## 実装結果

- `/tickets/:slug` の公開予約ページを追加した。
- 公開イベント、予約枠、残数、枠履歴は共通helperからcanonical `get_public_ticket_event` RPCを1回だけ呼んで取得する。
- request IDを保持して予約RPCの冪等再送を可能にした。
- 予約処理の状態を `request ID + 元payload + slug + status + reservation code` の単一トランザクションとして `WebApp` のメモリへ集約した。
- transaction `status` は `pending` / `succeeded` に限定し、結果不明時はpending、RPC成功時は予約番号を含むsucceededへ更新する。
- SPA内のリンク遷移・ブラウザ戻る・戻るスワイプで予約ページがアンマウントされてもtransactionを保持し、同じ予約ページへ戻るとpending payloadを復元して同一request IDで再送できる。
- RPC送信中にページを離れた後で成功レスポンスが返っても、WebApp側transactionへ `succeeded` と予約番号を保存するため結果を失わない。
- pendingを復元した時にイベントが既に下書き・削除され公開readが `null` でも、保存済みpayloadだけで同一request IDを再送して予約番号を回収できる。
- 未確定予約が別公演に残っている場合は新しい予約を開始せず、確認中の予約ページへ戻す導線を表示する。succeeded transactionは別公演の新規予約を妨げない。
- pending中のフルリロード・タブ離脱だけ `beforeunload` で警告する。氏名・メール等を `sessionStorage` / `localStorage` へ永続化する仕組みは追加しない。
- `reservationRequestId` を保持している間は予約枠radioだけでなく名前・メール・枚数・備考も固定し、再送payloadを変更できないようにした。
- 冪等再送では現在の残数に基づくクライアント枚数検証を再適用せず、保存済みの元payloadをそのまま再送する。予約成功後に残数が減った場合でも予約番号回収を妨げない。
- DB/PostgRESTから構造化されたエラーコード付きの確定エラーが返った場合はtransactionを破棄し、公開イベント・在庫を再取得してから次の操作へ進める。結果不明の通信失敗ではpendingを保持する。
- 確定エラー後の再取得にも失敗した場合は古い在庫を使い続けず、在庫をstale扱いとして新規予約を停止する。
- 満席スナップショットが後からキャンセル等で変化した場合に回復できるよう、「空席状況を更新」ボタンでcanonical public readを再実行できるようにした。自動ポーリングは追加しない。
- 予約成功後の再取得がエラーまたは `data: null` の場合も、現在のイベントと予約番号表示を維持するようにした。
- 受付期間・枠開始時刻に関する端末時計判定は案内と優先選択に限定し、公開状態と残数を満たす場合はRPCへ到達可能にした。最終的な時刻判定はDBの `clock_timestamp()` と行ロックを権威とする。
- 端末時計上で開始済みの枠は開始前の枠より後に選択候補とするが、時計ずれだけを理由に確定的には無効化しない。
- `closed` かつ予約枠履歴のないイベントは「自由席として受付中」と案内せず、「予約受付は終了しました」と表示する。
- 次の予約入力または新しいrequest IDでの送信開始時に前回の予約番号表示をクリアし、失敗した新規予約と過去の成功表示が同時に出ないようにした。
- 入力や予約枠を変更した時点で以前のエラー表示もクリアし、解消済みエラーを残さないようにした。
- 予約枠履歴だけが残り現在の枠が0件の場合は案内を重複表示しない。

## レビュー対応

- 未確定結果の保護は個別リンク無効化や `popstate` トラップを積み増さず、予約transactionをWebAppへ持ち上げてSPA遷移後も復元可能にすることで根本対応した。
- 「離脱中に成功した結果が消える」問題は、成功番号までWebApp側のsucceeded transactionへ保持して解消した。
- 「イベントが非公開化されるとpendingを再送できない」問題は、pendingの結果回収を公開イベントreadから切り離し、保存済みpayloadだけで再送できるようにして解消した。
- Data Routerへの全面移行、履歴操作の強制巻き戻し、ブラウザストレージへの個人情報保存は行わない。
- DBが明確に拒否した確定エラーではtransactionを解除して公開状態・残数を再取得し、再取得不能なら古いスナップショットを無効化する。通信結果が不明な場合だけ冪等再送待ちを維持する。
- 端末時計ずれへの対応としてサーバー時計同期機構は追加せず、クライアント時刻を確定的な受付拒否に使わない。受付開始・終了・枠開始の最終判定は既存DB RPCへ一本化する。
- 在庫変化への追随は自動ポーリングではなく明示的な手動更新導線とし、常時同期stateを増やさない方針とした。
- 親Stackの公開readは複数リクエスト＋stale判定群を廃止し、単一DB snapshot RPCへ整理した。

## 検証

- 親PRのdatabase CIでfresh migrationとcanonical public readを含むpgTAPを検証する。
- 公開予約ページ固有の挙動と親Stackの差分を分離した状態で維持する。
