# 公開チケット予約ページ 実装結果

## 実装結果

- `/tickets/:slug` の公開予約ページを追加した。
- 公開イベント、予約枠、残数を取得し、受付期間・満席・開始済み枠に応じて選択可否を制御した。
- request IDを保持して予約RPCの冪等再送を可能にした。
- 予約RPC成功後にレスポンス取得だけ失敗した場合、受付終了や枠開始後でも保持済みrequest IDによる再送だけを許可した。
- `reservationRequestId` を保持している間は予約枠radioだけでなく名前・メール・枚数・備考も固定し、再送payloadを変更できないようにした。
- DB/PostgRESTから構造化されたエラーコード付きの確定エラーが返った場合はrequest IDを解除し、別枠や入力を修正して新しい予約を開始できるようにした。結果不明の通信失敗ではrequest IDを保持する。
- 予約成功後の再取得がエラーまたは `data: null` の場合も、現在のイベントと予約番号表示を維持するようにした。
- イベント自体が受付期間外になった場合は入力欄と予約枠選択を固定し、再送時のpayloadとrequest IDを変えないようにした。
- イベントが受付中で選択中の枠だけが開始時刻を迎えた場合は、request IDを保持していない通常状態なら開始前かつ空きのある別枠へ切り替えられるようにした。
- 次の予約入力または新しいrequest IDでの送信開始時に前回の予約番号表示をクリアし、失敗した新規予約と過去の成功表示が同時に出ないようにした。
- 入力や予約枠を変更した時点で以前のエラー表示もクリアし、解消済みエラーを残さないようにした。
- 予約枠履歴だけが残り現在の枠が0件の場合は「予約可能な枠がありません」を1回だけ表示する。
- 公開イベント取得は共通helper側で埋め込みalias `windows` を使って予約枠を並べ替える。

## レビュー対応

- 受付境界後の冪等再送と、成功後再取得 `data: null` 時の予約完了表示維持に対応した。
- 通常時の別有効枠への切替と、冪等再送待ち中のpayload固定を状態で分離した。イベント受付中でもrequest ID保持中は全入力を固定し、request IDがなければ別の有効枠へ切替可能とした。
- DBが明確に拒否した確定エラーではrequest IDを解除し、通信結果が不明な場合だけ冪等再送待ちを維持するよう整理した。
- 入力変更時の旧エラー表示と、予約枠0件時の重複案内を修正した。
- 次の予約開始時に以前の予約番号を消すよう修正した。
- 公開画面のJSX構文エラーを修正し、修正後CIでlint/build成功を確認する。
- 親StackのDB・共通クライアント・管理画面のレビュー修正を同期した。

## 検証

- GitHub Actions CIで継続検証する。
- 公開予約ページ固有の挙動と親Stackの差分を分離した状態で維持する。
