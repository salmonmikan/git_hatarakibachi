# Issue 33 公開チケット予約PR 是正計画

## 対象

- P0: 匿名予約を成立させ、予約番号だけを返し、予約一覧・個人情報は公開しない。
- P1: 公開状態、削除状態、受付期間、予約枠とイベントの対応、数量上限、残り定員をDB内で原子的に検証する。
- P1: 一般の認証済みユーザーに付与されていたチケット3テーブルの管理権限を、既存の `admin_users.uuid = auth.uid()` パターンへ限定する。
- P2: 管理Tickets画面の `datetime-local` をローカル日時として対称変換し、無変更保存で時刻をずらさない。

## 実装方針

1. 既存migrationと既存データを変更せず、新規の前方互換migrationでRLS、GRANT、RPCを是正する。
2. 公開予約は公開wrapper RPCから非公開schemaの検証関数へ限定し、イベント行と予約枠行のロック中に条件確認とINSERTを行う。
3. 予約テーブルの直接書込み権限を匿名・認証ロールから除き、管理画面のキャンセルも管理者確認付きRPCへ限定する。
4. 日時変換を純粋utilityへ分離し、JST表示、UTC保存、無変更往復、日付跨ぎの回帰テストを追加する。
5. pgTAPで匿名、非管理者、管理者、受付条件、数量、capacity、旧データ互換を検証する。
6. 関係テスト、DB lint、ESLint、build、差分監査後に本是正差分だけをコミットする。
