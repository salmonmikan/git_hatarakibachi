# Issue #33 計画

## 目的
corich/TIGET のような外部サービスに依存せず、劇団内で運用できる最小限のチケット取り置きシステムを構築する。

## 対応範囲
- 役者・窓口別 URL または公演別 URL として利用できる公開予約ページを追加する。
- 自由席/簡易予約枠を選択して予約できるフォームを追加する。
- 決済・複雑な指定席管理は対象外とする。
- 管理画面で販売ページ、予約枠、予約一覧、キャンセルを扱えるようにする。
- Supabase の最小テーブル定義と RLS を追加する。

## 実装方針
- `ticket_events` を販売ページ単位、`ticket_windows` を日時/窓口/枠単位、`ticket_reservations` を予約単位として分離する。
- Web 側は `/tickets/:slug` を公開 URL とし、公開中かつ受付期間内の販売ページだけ予約可能にする。
- Admin 側は既存管理画面のルーティングに `tickets` を追加し、既存 UI の `.admin-view` 系スタイルに合わせる。

## PR #39 追加改修計画
- Sanity `performance` の `_id` を `ticket_events.sanity_performance_id` に保存し、管理画面で連携先を選択・参照できるようにする。
- Sanity 公演の表示リンクと既存 Studio workspace 導線を残し、未連携の販売ページは管理画面で明示する。公開状態へ変更する場合は連携を必須にする。
- 予約枠を編集できるようにし、削除は予約履歴を保持するソフト削除RPCへ限定する。残数を管理画面に表示する。
- 定員を既存予約数未満へ変更できないDB trigger、受付日時順序のDB/UI検証を追加する。
- 公開予約成功後に残数を再取得し、今回のレビュー指摘と既存の容量検証を維持する。

## PR #39 レビュー指摘7件の追加計画
- 現行headとreviewThreadsをGitHub Appで再取得し、outdated指摘と未解決・現行指摘を分離する。
- 既存のadmin_users限定RLS、公開予約RPCのイベント/受付条件検証、日時順序制約、予約成功後の残数再取得は現行コードで維持されていることを確認する。
- 全予約枠を削除したイベントが公開側で自由席へ変化しないよう、既存スキーマの履歴を使ってRPCとDBトリガーで拒否する。
- 管理画面の残数集計をRESTのmax_rows制限から切り離し、admin認証付きのDB集計RPCへ置き換える。
- 公開フォームの枚数上限を選択枠の残数と既存の上限10枚の小さい方へ合わせ、純粋な数量計算をNodeテストで検証する。
- 対象lint、Nodeテスト、build、pgTAP、git diff --checkを実行し、全体lintの既存失敗と今回変更を分離する。
