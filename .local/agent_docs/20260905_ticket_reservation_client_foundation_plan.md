# チケット予約共通クライアント基盤 実装計画

## 対象

- 公開イベント取得、予約作成、管理者キャンセルのSupabase呼び出しを共通化する。
- 公開イベント取得はDB側のcanonical read RPC 1回だけとし、イベント・予約枠・残数・枠履歴のスナップショット整合性をクライアントで再構築しない。
- `datetime-local` とISO日時の相互変換を共通化する。
- 受付開始・終了境界と予約可能枚数の計算を共通化する。
- request ID付きの冪等予約呼び出しを既存の備考入力と両立させる。

## レビュー対応方針

- DB側の受付境界条件とクライアント側の再評価タイミングを一致させる。
- 公開readの競合指摘に対して個別の再取得・列比較を積み増さず、DBの単一スナップショットを権威とする。
- 公開フォームの備考入力は仕様として維持し、未指定時はcanonical RPCへ `null` を明示送信する。
- 境界時刻ちょうどにタイマーが発火しても、次の評価が失われないようにする。

## 確認方針

- Node標準テストで日時変換、境界、予約枚数計算を確認する。
- canonical public readはpgTAPで権限・イベント・枠履歴・残数を同時に確認する。
- GitHub ActionsのCIを確認する。
- UI固有ロジックはこの層へ持ち込まない。
