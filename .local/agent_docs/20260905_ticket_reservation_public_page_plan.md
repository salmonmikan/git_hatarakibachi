# 公開チケット予約ページ 実装計画

## 対象

- `/tickets/:slug` の公開予約ページを追加する。
- 公開イベント、予約枠、残数は共通のcanonical read RPCから取得し、受付期間・開始済み枠・満席状態を画面へ反映する。
- 予約処理は `request ID + 元payload + slug + status + reservation code` を1つのトランザクション状態として `WebApp` が保持する。
- request IDを保持して通信失敗時の冪等再送を可能にし、予約ページのアンマウント後も同一リクエストを回収できるようにする。
- 予約成功後は予約番号をトランザクション状態にも確実に保持し、残数再取得失敗と予約成功を区別する。

## レビュー対応方針

- 予約RPCが成功してレスポンスだけ失敗した場合、受付境界を越えても同一request IDの再送を許可する。
- SPA遷移や履歴ナビゲーションを個別に禁止せず、予約ページがアンマウントされてもWebApp側のトランザクション状態を残す。
- pending中に公開イベントが非公開・削除されても、保存済みpayloadだけで既存request IDを再送して予約番号を回収できるようにする。
- RPC成功時は、ページが既にアンマウントされていても `succeeded` と予約番号をWebApp側へ保存する。
- 入力内容は再送時に変更させず、同一request IDと同一payloadの関係を保つ。
- 氏名・メール等をブラウザストレージへ永続化する仕組みや、履歴遷移を押し戻すルーター制御は追加しない。

## 確認方針

- ESLint、Vite build、Node標準テスト、GitHub Actions CIを確認する。
- 公開ページの受付可否とDB側の予約制約が矛盾しないことを確認する。
- pending / succeeded のトランザクション状態がSPA遷移を跨いでも意味を失わないことを確認する。
